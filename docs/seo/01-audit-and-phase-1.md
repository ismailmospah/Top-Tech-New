# Phase 1 — Technical SEO foundation and the Arabic URL architecture

Internal working document (never deployed — see `.vercelignore`).

## The audit

### Architecture as found

A hand-written static site, no framework and no build step. Two pages
(`index.html`, `contact.html`) share `style.css`, `lang.js`, `transition.js`, and a
per-page script (`main.js` / `contact.js`). GSAP, ScrollTrigger, Lenis and Three.js
load from jsDelivr; a WebGL canvas, a preloader, a custom cursor, scroll-driven
GSAP animations and a marquee make up the visual identity.

### The problem that mattered most

Language was decided at runtime. `lang.js` held a dictionary of ~75 keys, read a
`toptech-lang` value out of `localStorage`, and rewrote every `[data-i18n]` element
in place. The consequences for search:

- **One URL served both languages.** There was no Arabic URL to rank, link to, or
  cite. Arabic existed only inside a JavaScript object.
- **Crawlers always saw English.** Googlebot has no `localStorage`, so the Arabic
  version was effectively invisible — the single largest SEO gap on the site, and
  the one the business cares most about.
- `hreflang` was impossible, because there was nothing to point at.

### Everything else that was missing

| Item | Before |
| --- | --- |
| `robots.txt` | absent |
| `sitemap.xml` | absent |
| `rel=canonical` | absent on both pages |
| `hreflang` | absent |
| Structured data | none |
| Open Graph / Twitter | homepage only; `contact.html` had none |
| `<html lang>` | hard-coded `en`, corrected by script after load |
| Asset paths | relative (`assets/…`, `style.css`), so no page could live in a subdirectory |
| Internal links | pointed at `contact.html`, which 301-redirects to `/contact` |

Already correct and deliberately left alone: unique titles and descriptions per
page, the Facebook domain verification tag, Google Analytics (`G-NXWC3SFZJ2`), the
Meta Pixel and the TikTok Pixel.

## What Phase 1 changed

### 1 — Language now lives in the URL

| Language | Homepage | Contact |
| --- | --- | --- |
| English | `/` | `/contact` |
| Arabic | `/ar` | `/ar/contact` |

**No existing URL changed.** `/` and `/contact` are exactly where they were; the
Arabic pages are new additions beside them. Each page ships its own language in the
markup — `<html lang="ar" dir="rtl">` with `is-ar` on `<body>` — so both versions
are fully crawlable with no JavaScript required.

`lang.js` was rewritten around that. It no longer translates the DOM: it reads the
language from `<html lang>`, still exposes `window.TT_T` (which `contact.js`
depends on for form strings), still splits headings into `.char` spans for the GSAP
animations, still rebuilds the marquees, and turns the toggle into a navigation to
the translated URL. The toggle's target is read from the page's own `hreflang`
annotation, so the button and the SEO markup can never disagree.

Returning visitors are protected: a small script in the head of `/` sends someone
who previously chose Arabic to `/ar`. It is skipped on back/forward navigation so
the Arabic page cannot become a history trap, and crawlers — having no
`localStorage` — never see it.

### 2 — Arabic pages are generated, not hand-copied

`tools/build-ar.mjs` builds `/ar` from the English source plus the dictionary in
`lang.js`: it swaps each `[data-i18n]` element's content, rebuilds the marquees,
translates `aria-label` text, adds `is-ar`, rewrites internal links to stay inside
the Arabic site, and derives the Arabic structured-data graph from the English one.

This matters for the design constraint. The Arabic page is the *same* markup —
same classes, same animation hooks, same layout — with different text. The two
languages cannot drift apart, and no Arabic page was designed by hand.

The tool asserts that the analytics snippets survived the transformation and fails
loudly if they did not.

### 3 — Technical SEO

- `robots.txt` — allows everything, and names the crawlers that matter
  (Googlebot, Bingbot, **OAI-SearchBot** for ChatGPT Search, ChatGPT-User,
  PerplexityBot, Google-Extended, Applebot, DuckDuckBot) explicitly, so no future
  blanket rule can hide the site from search or AI answer engines by accident.
  Points at the sitemap.
- `sitemap.xml` — generated by `tools/build-sitemap.mjs` from the route table.
  Four canonical URLs, each carrying reciprocal `xhtml:link` hreflang annotations
  (self + counterpart + `x-default`). No redirects, no `.html` duplicates.
- **Canonical** on all four pages, each self-referencing. Arabic pages canonicalise
  to themselves, never to English.
- **hreflang** on all four pages: `en`, `ar`, `x-default` → English. Reciprocal.
- **Open Graph and Twitter cards** on all four pages, including `og:locale`,
  `og:locale:alternate` and image alt text. `contact.html` had none before.
- **Structured data** — an `@graph` of `Organization` (real contact details, real
  social profiles, `areaServed` Saudi Arabia + Egypt, and an `OfferCatalog` of the
  six services actually shown on the page), `WebSite`, and `WebPage` /
  `ContactPage` with a `BreadcrumbList`. No address, no reviews, no ratings — the
  business information does not support them, so none was invented.
- Asset and script paths made root-relative, which is what lets pages live under
  `/ar/…` at all.
- Internal links now point at `/contact` rather than `contact.html`, removing a
  301 hop from every internal link.

### 4 — Routing

`vercel.json` gained `trailingSlash: false` (so `/ar/` normalises to `/ar` and no
duplicate URLs appear) and two redirects mirroring the existing pattern, sending
`/ar/index.html` and `/ar/contact/index.html` to their clean URLs. The build
command is still a no-op: the deployment remains plain static files, and the
generators run locally with their output committed. If a tool ever breaks, the
site is unaffected.

## Tooling added

| File | Purpose |
| --- | --- |
| `tools/routes.mjs` | the route table — one entry per page, English + Arabic. Single source of truth for both generators. |
| `tools/build-ar.mjs` | generates the Arabic pages |
| `tools/build-sitemap.mjs` | generates `sitemap.xml` |
| `tools/dev-server.mjs` | serves the site locally using the real `vercel.json` rules, for checking routing and rendered HTML |

All are zero-dependency Node scripts, excluded from the deployment.

## Deliberately not done

- No redesign. No colour, type, layout, animation or component was changed.
- No `llms.txt` — no justified reason, and solid fundamentals matter more.
- No fake schema, no invented metrics, no doorway pages.
- Service pages, case studies and articles are Phase 2 onward.
